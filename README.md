## 🛠 Architecture & Development

> **Interactive Social Drama Platform** — Event Sourcing 코어(PostgreSQL=SoT) 위에
> transactional outbox → NATS JetStream → 프로젝터가 읽기 모델을 세우고, 이산 tick
> 엔진이 100명의 AI 액터를 굴린다. LLM은 NATS request-reply의 AI Runtime 한 곳으로만 부른다.

### Architecture at a Glance

| 축 | 결정 | ADR |
|----|------|-----|
| 상태 모델 | Event Sourcing — 모든 변화는 불변 이벤트, PostgreSQL이 SoT | [002](docs/adr/ADR-002-event-sourcing.md), [005](docs/adr/ADR-005-postgresql-source-of-truth.md) |
| 읽기 모델 | CQRS — es에서 재구축 가능한 프로젝션(OpenSearch·Redis·PG-read·Kuzu) + Qdrant 시맨틱 기억 | [003](docs/adr/ADR-003-cqrs-projection.md) |
| 메시징 | NATS JetStream + transactional outbox + Event Dispatcher (단일 리더 relay) | [004](docs/adr/ADR-004-nats-jetstream.md), [017](docs/adr/ADR-017-event-dispatcher.md) |
| 기억 | 5계층 Memory Fabric + Context Fabric (토큰 예산 조립) | [008](docs/adr/ADR-008-memory-fabric.md), [009](docs/adr/ADR-009-context-fabric.md) |
| 시뮬레이션 | 이산 tick(60s) + 액터 LOD(Hot/Warm/Cold) + asyncio 액터 런타임 | [011](docs/adr/ADR-011-tick-engine.md), [012](docs/adr/ADR-012-actor-runtime.md) |
| 서사 | Director AI — 제한된 간접 개입만 (세계 사건·관측·아크) | [013](docs/adr/ADR-013-director-ai.md) |
| AI | AI Runtime — NATS request-reply, task×tier 라우팅(로컬 ollama·호스티드), 예산 하드 캡 | [018](docs/adr/ADR-018-ai-runtime-layer.md) |
| 전송 | SSE(피드 스트림) + WebSocket(상호작용) hybrid | [010](docs/adr/ADR-010-websocket-sse-hybrid.md) |
| 배포 | dev=Compose(호스트 프로세스), prod=K8s+Helm(예정) | [019](docs/adr/ADR-019-deployment-architecture.md) |

전체 결정 기록: **[docs/adr/](docs/adr/README.md)** (ADR-001~020, 20종)

### Getting Started

요구: **Node ≥ 22 · pnpm 10.34+ · Python 3.12(uv) · Docker** · *(선택)* **ollama** — 로컬 LLM

```bash
# 1) 의존성 + 검증
pnpm install && pnpm typecheck
uv sync && uv run pytest

# 스키마 코드젠 (packages/schemas가 단일 원천 — 산출물은 커밋 대상)
uv run --package lf-schemas python packages/schemas/scripts/generate.py   # Python 모델
pnpm --filter @livingfeed/schemas generate                               # TS 타입
```

```bash
# 2) 저장소 기동 — 호스트 포트는 infra/compose/.env 기준(PG 5433 · Redis 6380 · NATS 4222)
cd infra/compose
docker compose --profile core up -d   # 저장소 7종: PostgreSQL·Redis·NATS·nats-test·Qdrant·OpenSearch·MinIO
# 또는 --profile full 로 gateway·feed-api·projector까지 컨테이너로
```

```bash
# 3) (선택) 로컬 LLM — 없으면 규칙 폴백으로 GPU 0
ollama pull qwen3:8b   # LF_LOCAL_MODEL 기본값
```

```powershell
# 4) 백엔드 전체 기동 (호스트 프로세스, 유휴 저전력 기본) — 액터 15 · Hot 6 · idle · local
infra/scripts/run-backend.ps1
#   -Mode lively            더 활기찬 세계(상시 Hot 바닥, GPU↑)
#   -MaxActors 40 -HotStart 12   규모 조절 (20명 초과는 40B+ 모델 권장 — 기동 로그에 vRAM 안내)
#   -AiProvider rule        LLM 없이 규칙 반응 (GPU 0)
```

```bash
# 5) 웹
pnpm --filter @livingfeed/web dev   # → http://localhost:3000
```

주요 런타임 노브(env): `LF_MAX_ACTORS` · `LF_HOT_START_ACTORS` · `LF_WORLD_MODE`(idle/lively)
· `LF_AI_CONCURRENCY` · `LF_DECIDE_CONCURRENCY` · `LF_PG_POOL_MAX` — 상세: [infra/compose/README.md](infra/compose/README.md)
